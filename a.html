OVERVIEW//

Grid load doesn't spike randomly.

State load dispatchers plan capacity against a curve that moves for reasons that show up on a calendar, not just in yesterday's weather: a festival keeps millions of lights and kitchens running past midnight, an IPL night puts a television and an AC in every living room at the same hour. Most demand-forecasting baselines ignore that context entirely and just repeat last week's number. This project tests whether a model that's told about the calendar can beat one that isn't — and by how much.

FEATURE BANK//

Three families of signal, seven features.

CALENDAR
  • day_of_week
  • month
  • is_weekend

Captures the weekly and seasonal rhythm every grid has, independent of any single event.

AUTOREGRESSIVE
  • demand_lag_1
  • demand_lag_7

Yesterday's load and the same day last week — the two features that end up carrying the model.

EVENT
  • is_festival
  • is_ipl_day

Diwali, Dussehra, and IPL match windows (2019 season + the 2020 UAE-hosted season), flagged from a curated date list.

EXPLAINABILITY//

Ask the model what it's actually looking at.

A SHAP summary plot on the tuned XGBoost model, ranked by mean absolute SHAP value across the test set.

Reading the plot

demand_lag_1 dominates by a wide margin — high recent demand (pink) pushes predictions up sharply, confirming the model leans hardest on short-term momentum. demand_lag_7 plays a stabilizing counter-role. is_ipl_day shows a real, if smaller, positive push on match days. is_festival barely registers — a signal worth digging into further, since the raw event flag alone may be too blunt to separate a demand-suppressing holiday from a demand-raising one.

LIMITATIONS & NEXT STEPS//

What this doesn't solve yet.

  • Festival flag is too blunt. A single is_festival bit can't tell a demand-suppressing holiday from a demand-raising one — splitting it by festival type is the obvious next experiment.
  • No weather signal. Temperature and humidity almost certainly explain some of what demand_lag_1 is currently absorbing; adding them would be a fairer test of the event features.
  • Single-state scope. The pipeline filters to Telangana only — extending it across states would test whether the event effects generalize or are local.
  • Point forecasts only. No prediction intervals yet, which is what a real dispatcher would actually need to plan capacity margins.
